**Lists and signup boxes on sites with no adapter.**
A bare ARIA combobox input (`input role="combobox"` that is not react-select's, a datalist, Lever's location box, or a "Start typing..." box; Eightfold's Octuple Select draws its lists this way) is opened once while the form is read (`readAriaListOptions`, `packages/browser/src/handshake-executor.ts`), sharing react-select's limit of 40 list openings per read.
Its options are the visible `role="option"` items of the listbox its `aria-controls` or `aria-owns` names (on the input or up to three ancestors), else of the one visible `role="listbox"` on the page; the list is then closed with Escape and a blur, and opening it saves nothing.
Any bare ARIA list that shows options on opening, readonly or editable, becomes a plain list, chosen by clicking its option in the listbox it names and kept when the input shows the option's text, or its dialing code on a phone-country picker ("+1" for "United States (+1)").
An editable list is typed into only when the option is not shown on opening, and a list that shows no options on opening stays a type-ahead (Track 37, `076-live-eightfold-phenom-and-rippling-forms.md`).
A searched list whose options were read types the option as the site shows it for a saved answer: the exact option, the one pronoun option the saved pronouns start, or the standard-answer option for a legal or background answer (`planAutofill`, `packages/browser/src/autofill-planner.ts`).
A "Country code picker" (or "Phone country code") list takes the profile country, the same rule as Greenhouse's phone Country list.
A "Sex" question is a voluntary self-identification question (`packages/browser/src/ats/field-roles.ts`; "sex offender" is not): it takes the candidate's saved answer only when exactly one offered option matches and the list lets the candidate decline, and otherwise pauses as a sensitive question whose answer is never stored.
A job-alert, newsletter, or talent-community signup box (an id naming notify, job alert, alert email, subscribe, newsletter, or talent community, as Phenom's `notifiedEmail` box beside a posting) is never an application field (`isSignupField`, `packages/browser/src/form-recognition.ts`): the navigation walk goes on to the posting's Apply entry, and the planner leaves the box empty.
The same boxes are recognized by their container too (Track 77): a control is never read when one of its six nearest ancestors has an id or class naming a newsletter, subscription, mailing list, job alert, or talent community or network, as long as that container holds no file upload and at most four controls a person fills (`inSignupBox` in `collectControlsIn`).
This covers Amperity's footer newsletter form (`styles_newsletter_signup_form__…`) and Lucid Motors' Subscribe block (`SubscribeForm_formBodyWrapper__…`), captured 2026-11-27; an application section whose container says "subscription" but holds a resume upload is still read (`pnpm test:browser:site-navigation`).
A list's own search box labelled only "Search" (Rippling's phone-country popover) is not a question and is left empty (`isListSearchBox`).
A control inside a wrapping label takes that label's `aria-labelledby` text first, so Rippling's uploads, wrapped in `label[aria-labelledby]` whose own text only says "Upload", read as their question ("Resume").
Since Track 80 the auto-submit policy submits these runs when nothing else holds them (`079-auto-submit-on-sites-without-an-adapter.md`).
Regression: `pnpm test:browser:unrecognized-forms` (derived fixtures `aria-list-application.html`, `labelledby-application.html`, and `job-alert-posting.html`), with fast cases in `pnpm test:browser-worker:fast` and a run through `startBrowserRun` in `pnpm test:browser-worker:local`.
