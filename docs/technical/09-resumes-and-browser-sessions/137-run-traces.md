**Run traces: a Playwright trace kept when a run does not end cleanly (Track 42).**
The candidate asked for screenshots before and after every action the agent takes; taken literally, waits of a few seconds around each action would add minutes per application, could change how sites behave, and would fill gigabytes a day.
Instead every real run records a Playwright trace with no added waits: `openProfilePage` (`packages/agent/src/browser-orchestrator.ts`) starts it for each generic start, continue, and submit, and for each Workday start, continue, and submit, so the Workday, iCIMS, and Oracle steps inside them are traced too.
The default options are `RUN_TRACE_OPTIONS` in `packages/browser/src/run-trace.ts`: the screencast film strip and the actions with their parameters, with no per-action screenshots (`snapshots.screen: false`), no DOM snapshots, no accessibility snapshots, and no sources.
The candidate chose this default, "Film strip by default (Recommended)", on 2026-11-26, after the 2026-11-25 measurements below showed the per-action screenshots cost almost all of the overhead.
Setting `INTERNSHIP_AGENT_TRACE_SNAPSHOTS=1` switches to `RUN_TRACE_SNAPSHOT_OPTIONS`, which add a screenshot before and after each action (`snapshots.screen: true`) for debugging one site and change nothing else.
`INTERNSHIP_AGENT_TRACE_SNAPSHOT_HOSTS`, a comma-separated list of host names, limits that setting to those hosts by exact, case-insensitive match (a subdomain does not match); it is decided per opened browser from the address it opens (`traceSnapshotsWanted`), so a Workday hand-over decides again at the Workday address.
In Playwright 1.63 DOM snapshots are what start the network recorder, which writes every request and response with its headers (Cookie, Set-Cookie, Authorization) and attaches response bodies, and DOM snapshots keep input values; turning them off records no network at all.
Accessibility snapshots put every input's value in the trace, passwords included, so they stay off.
Scrubbing a saved zip was rejected: it cannot clean response bodies or every shape of token.
Typed candidate values remain in the actions' parameters, which is allowed locally like the other evidence.
Secrets are kept out by not recording while they are typed: `wrapUntracedMethods` saves the trace so far as a part and stops recording around Workday's sign-in, account creation, and verification link, and iCIMS's profile creation, sign-in, and verification link (resumed after), and around Greenhouse's and Oracle's emailed security codes, after which nothing more is recorded.
Every saved part, in both modes, is checked fail-closed before it is kept (`checkRunTraceZip`, with a small zip reader on `node:zlib`): `trace.network` must be empty, no DOM or resource snapshot event may appear, every line must parse, and the saved Workday or iCIMS password of the run's host may not appear raw or JSON-escaped.
A failed check, a tracing error, or saved account values that cannot be read deletes every part and logs "Run trace not kept: <why>."
A run that ends cleanly (submitted, or a clean awaiting-approval; a hand-over to a Workday run, which records its own) discards its trace; a run that stops, pauses, or fails keeps it, including a failure before the run row was saved.
Kept traces are `<data>/applications/<job>/run-traces/trace-<run id or "job">-<start time>.zip`, with `-1`, `-2`, … when the trace was saved in parts (directory mode 700, files mode 600), and the timeline logs "Run trace saved: <relative paths>; view it with pnpm run:evidence --run <ref>."
Playwright's intermediate files go to the profile's `trace-artifacts/` folder (mode 700, the persistent context's `tracesDir`).
After each run `pruneRunTraces` deletes kept traces older than 14 days, then the oldest while all of them take more than 1 GiB, parts folders older than a day, and every file in `trace-artifacts/` older than a day by its own time (its shared `resources/` folder is refreshed by every run), then the folders left empty.
`pnpm run:evidence --run <ref>` lists the run's kept traces and `--job <ref>` all of the job's, each with its size, time, and the command that opens it: `pnpm exec playwright show-trace <path>`.
A page that never finished opening now keeps its trace and closes its browser before the error is passed on.
The stop captures' screenshot and region read appear in the trace as actions; that is expected.
On 2026-11-25, with per-action screenshots on, the Handshake fixture fill went from 1.15 s to 3.20 s (+179%, 2.3 MB) and the Workday fixture's first walk from 3.07 s to 12.98 s (+322%, 16.3 MB); a one-off comparison put almost all of that on the per-action screenshots, the screencast alone adding about 3% and 0.4 MB.
Measured on 2026-11-26 by scenario (H) of `xvfb-run -a pnpm test:browser:stop-evidence` (medians of three local fixture runs in fresh contexts), the default mode took the Handshake fixture fill from 1.15 s untraced to 1.17 s (+1.8%) with an 89 KB trace, and the Workday fixture's first walk from 3.11 s to 3.16 s (+1.6%) with a 0.41 MB trace.
In the same run the snapshot mode took the Handshake fill to 3.21 s (+179.5%) with a 2.3 MB trace and the Workday walk to 13.02 s (+319.4%) with a 16.3 MB trace.
The local fixtures have no network waits, so the relative overhead on a real site is smaller than measured, but the added seconds per action are of the same order.
Regressions: scenarios (B) to (H) and (J) of `xvfb-run -a pnpm test:browser:stop-evidence` (no cookie, header, or body value in a trace of a page that sets them in either mode, no per-action screenshot by default and some in snapshot mode, the contrast with DOM snapshots, passwords and codes never recorded, the fail-closed check, pruning, the overhead report for both modes, and the setting's host rules), the trace-listing and event cases of `pnpm test:agent:evidence`, and the run-trace wiring case of `pnpm test:browser-worker:local`.
Discovery and posting-page reads fetch over HTTP and open no browser page, so no run trace applies to them.
Boundary: `openProfilePage` itself (a persistent Chromium on the candidate's profile) is exercised only through the typecheck, the run-trace module in real Chromium, and the orchestrator's calls on a fake trace; no live run was traced.
