**Read-back before the submit click.**
`submitBrowserRun` reloads the form for the click, so every answer the approval covered must still be there: an approved fill, choice, check, or upload whose field the reloaded form does not show holds the run before anything is typed (`absentDecisionFields`, `packages/browser/src/handshake-executor.ts`): one `form-changed` safeguard pause, the approval withdrawn, nothing clicked.
After the fills, every choice on a radio question (native radios, Ashby's single-choice questions and Yes/No pairs) is read back from the page without opening any list (`choicesNotTaken`, through the page adapter's `readFields`); a choice the page does not show as made, a field gone from the page, or a read that fails pauses that field (`"<label>" did not take the choice`), the approval withdrawn, nothing clicked.
Lists, check boxes, and type-aheads are not read back.
Ashby names a single-choice question's radios `<form render id>_<field path>`, and the render id is new on every page load (read-only loads of a public Ashby page, 2026-11-25), so the agent identifies these questions by their field path (`data-field-path`), maps Ashby's submit field errors (`fieldEntryId`) to it (`ashbyFieldPath`), reads the chosen option from Ashby's own state (the option's `data-checked`), and chooses by clicking the option's label once and waiting for Ashby to show it chosen (a click on the chosen option would clear it).
Before this, every submit-time reload silently skipped an approved Ashby single-choice answer (Track 25).
