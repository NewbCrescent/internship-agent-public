**Stop evidence: a capture the first time each kind of stop happens (Track 42).**
Real runs on 2026-11-25 and 26 stopped in ways that saved no page capture, so their markup had to be guessed.
Workday history-row pauses ("did not add a … row", a row control that did not respond) saved nothing, so the cause of Compassion run <run id>'s pauses is still unconfirmed.
A run that failed before its run row was saved kept only an event text, as the ZOLL Workday start on job <run id> did with its 30-second locator timeout.
Step transitions, such as Littelfuse's lingering hidden resume input, were inferred and never captured.
Pauses on sites with no adapter ("How should X be answered?", "the field did not respond in time", "no suggestion matched") saved no DOM, and Track 35 guessed Eightfold's markup wrong.
"No application form was found" stops on career wrappers (ViaSat's careers page with `?icims=1`) saved no capture of the page or its iframes.
Now `saveStopEvidenceQuietly` (`packages/agent/src/submit-evidence.ts`) saves one capture for the first stop of each kind in a run, while the page is still open.
The kinds (`STOP_KINDS`, `packages/browser/src/stop-evidence.ts`) are `history-row`, `unfillable-field`, `unanswerable-question`, `no-form`, `run-failed`, and `step-transition`.
`history-row` is an open Workday pause on a `history:work:` or `history:education:` row whose question says Workday did not add the row or a row control did not respond; it is wired after the Workday walk at start and on continue, and its region is the Work Experience or Education section.
`unfillable-field` is a field the page would not take (applyDecisions' `unfilled`, never a covering dialog, which Track 39 captures) on generic start and continue, or a Workday pause that says the agent could not fill a field; its region is the field's form-field container.
`unanswerable-question` is an open question with no answer, no draft, and no safeguard or upload on a site with no adapter (start: the ATS flow is not automatic; continue: the ATS is unconfirmed or unknown); its region is the field.
`no-form` is "No application form was found (or reached) at …" thrown during a generic start, saved for the job (no run row exists yet); its region is the page with its iframes and Apply-like controls.
A generic continue whose reopened page shows no form ("No application form was reached at …") saves a run-level `no-form` capture the same way before it throws, and the run stays paused.
`run-failed` is a Playwright error (a `TimeoutError`, or a message such as `locator.focus: …`) during a generic start or a Workday walk in fill mode, saved for the job at start (the ZOLL case) and for the run on continue; never in submit mode, which may be after a click.
`step-transition` is a blocked Workday walk with none of Workday's own errors ("did not move to the next step within 20 seconds", "could not read any field on this step"); the existing `workday-errors` evidence is still saved beside it.
An Oracle email step that did not show its email box and Next, did not move past the step, led to an unrecognized step, or kept its Next unclickable, before any code was typed, saves a `step-transition` capture too (Track 63); code-entry stops are not captured.
Each capture holds the full-page screenshot, the visible text redacted like post-submit evidence, the URL without its query, the site's alert text, the stop's reason and field label, and a bounded excerpt of the region.
The excerpt is read in the page by `readStopRegionIn` without clicking, focusing, typing, tagging, or scrolling, and through the adapter's `stopRegion` (`packages/browser/src/handshake-executor.ts`).
It keeps at most 12,000 characters, 600 elements, and 30 levels; drops scripts, styles, comments, and shadow roots; redacts every text node (emails, URL queries, digit runs of seven or more) and clips it to 160 characters; replaces textarea and contenteditable contents with "[text not kept]"; and marks a hidden element `ia-hidden=""`.
Only an allow-list of attributes is kept (ids, names, `for`, Workday and agent tags, aria references and states, type, role, query-stripped `href`, `src`, and `action`, placeholder, class, and a few test ids), never `value`, `checked`, `selected`, `style`, event handlers, or other `data-*` attributes, so no typed, default, or hidden-token value is kept.
A page-level region also lists up to 20 iframes (query-stripped `src`, title, name, size, visibility) and up to 20 Apply-like controls (Apply, Start, Continue, Next, Submit, I'm interested, Sign in, Create account, Register, Guest, Upload).
The agent side redacts every text again, replaces the account's email and password with "[redacted]" on Workday runs, replaces each quoted value in the reason with `"[value]"` (so "no suggestion matched" never keeps the agent's value), and never names a history row's company or school.
A Playwright failure keeps only its first line: the call log, which names resolved elements with their values, is dropped.
Each kind is captured once per run, and a run keeps at most five captures (`STOP_CAPTURES_PER_RUN`), counting the ones already stored for it; a job-level stop is one stop of one attempt.
Captures live in `<data>/applications/<job>/stop-evidence/<time>-<run id or "job">-<kind>/` (directory mode 700, `evidence.json` and `screenshot.png` mode 600), and the newest 20 per job are kept (`STOP_CAPTURES_KEPT_PER_JOB`); older folders are deleted after each save.
The timeline logs "Stop evidence saved (<kind>): <relative path>; view it with pnpm run:evidence --run <ref>." (or `--job <ref>` before a run was saved), and a capture that fails logs "Stop evidence not saved." and never changes the run.
`pnpm run:evidence --run <ref>` merges the run's post-submit and stop evidence newest first, and `--job <ref>` shows the job's, with "Run: none (the run stopped before it was saved)" for a job-level stop.
A stop entry prints its kind and reason, the field, the site's error text, the region (anchor, length, and whether it was cut), the frames, the Apply-like controls, the screenshot path, and the redacted visible text.
Stop captures are saved before any submit click, so the automatic retry counts the `stop` outcome as pre-submit (`PRE_SUBMIT_OUTCOMES`, `packages/agent/src/automatic-retry.ts`); they live outside `submit-evidence/`, so no submit-attempt reader sees them.
Regressions: the "stop evidence (Track 42)" block of `pnpm test:agent:evidence` (redaction, the per-run cap, job-level captures, `run:evidence`, per-job retention, quiet failure, and the stop builders), the "stop evidence and run traces (Track 42)" and Workday "stop evidence (Track 42)" blocks of `pnpm test:browser-worker:local` (one per kind wired), the two Track 42 cases of `pnpm test:agent:retry`, and scenario (A) of `xvfb-run -a pnpm test:browser:stop-evidence` (the in-page reader in real Chromium, read-only).
Not wired: generic continue failures, submit-time stops (post-submit evidence covers them), closed postings, walls, and several-page stops, which name their own reasons.
The causes of the Compassion and ZOLL stops stay unconfirmed until the next real run saves their captures.
