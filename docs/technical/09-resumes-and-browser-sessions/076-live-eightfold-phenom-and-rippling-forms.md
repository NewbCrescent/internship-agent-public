**Live Eightfold, Phenom, and Rippling forms (Track 37).**
Track 35's list reading was modeled on Octuple's public source, and on the real Lockheed Martin run (<run id>) it changed nothing: every list was read with its options, and every choice failed with "the field did not respond in time".
Read-only captures of the live forms on 2026-11-25 (a disposable browser profile, headful under Xvfb; nothing typed, chosen, uploaded, or submitted) showed why, and the fixtures `eightfold-application.html`, `phenom-application.html`, and `rippling-application.html` (`testing-harness/browser/fixtures/`) are derived from them with fictional names and `.example` hosts.
Eightfold's Octuple lists are editable `input role="combobox"` boxes that filter as you type, yet show every option on opening (`ul#list-N[role=listbox] > li > button[role=option]`), so Track 35 sent them through the type-ahead path, which clicks, clears, and types.
Any bare ARIA list that shows options on opening is now a plain list, chosen by clicking its option in the listbox it names; an editable one is typed into only when the option is not shown, and a choice the input does not show pauses with "the site did not keep the choice" (`chooseComboboxOption`, `packages/browser/src/handshake-executor.ts`).
Eightfold's careers site opens a welcome dialog on load (`role="dialog" aria-modal="true"` over the whole page) that takes every trusted click until it is closed.
When a trusted click on a bare list or its option times out (`clickBareList`), a site announcement is closed with its own close control, but only when the dialog holds no form field and no frame, offers a "Close…", "Dismiss…", or "×" control, and has no sign-in, verification, CAPTCHA, cookie, consent, session, terms, privacy, error, submission, or application wording (`chooseAnnouncementClose`, `packages/browser/src/announcement-dialog.ts`); an accept or continue control is never clicked.
If the click still does not land, it is dispatched to the list's own element only when no CAPTCHA or site check and no modal dialog is still shown; otherwise the list pauses with "a site check covers the form" or "a dialog covers the form", so a safeguard is never clicked through.
What kept every list click from landing after the resume upload on run <run id> is not confirmed, since the captures could not upload a file; the fixture's `?blocked=1` layer is an assumed stand-in, and the next real run confirms the fix.
The phone "Country code picker" already shows the country as "🇺🇸 (+1) United States of America", and typing the profile country first cleared it; a country field that already shows the profile's country (a leading flag and dialing code are ignored, `countryKey` in `packages/browser/src/autofill-planner.ts`) is kept, and one showing another country is chosen to the profile's.
A bare "+1" names no country, so a picker showing only a dialing code is still chosen.
MITRE's Phenom form labels its phone country list "Country Phone Code", which is now read as the profile country and takes "USA", never a US territory.
Rippling's Pronouns list offers each set alone and combined with "they/them/theirs"; saved pronouns naming one set take the one option naming one set they start, and saved pronouns naming two sets are never narrowed to one.
Rippling's custom questions carry nothing that names their control (no label, aria name, or placeholder, and a random `name` that changes on every load): the question is a `p` in a block written before the field, in a container holding no other question's control, and that text is now the label, read after the placeholder and before the name (`questionTextBefore` in `collectControlsIn`).
Rippling's dropdown custom questions (`div role="combobox"`) and Yes/No questions (`div role="radiogroup"` of `div role="radio"`) are not read as fields at all; that is left open.
A saved protected self-identification answer is still used only on a single matching option, and a race question with no saved answer still pauses for the candidate.
These runs still wait for the candidate's approval as an unrecognized or Rippling site, and nothing about automatic submission changes.
That was not true for MITRE's Phenom form, which was taken for Workday and approved by the auto-submit policy; Track 38 (077-site-ownership-and-the-submit-target.md) fixed it.
