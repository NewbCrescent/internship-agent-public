A resume field receives the candidate's current uploaded resume for the run's profile, byte for byte: `default` on default-profile runs, `handshake_internal` on alternate-profile runs (Handshake Quick Apply / Apply, a form asking for a transcript, or a company pinned to the transcript profile); Workday chooses per step, switching when a step asks for a transcript.
The decision records basis `base_resume`, and the run records `base_resume_id` (null when the run uploads no resume, for example a Quick Apply run that keeps the Handshake account's attachment).
Nothing is printed for that upload and the generated resume's page limit does not apply.
Each upload (start, continue, and submit, including auto-submit) re-checks that the file is still the channel's current upload (a replacement since the run was planned stops the run) and matches its SHA-256 (a missing or changed file stops it), then copies the bytes to `<profile data dir>/applications/<job>/uploads/<base resume id>/<original file name>` (mode 600) and uploads that copy, so the site receives the candidate's own file name.
Without an upload for that profile, or with `INTERNSHIP_AGENT_RESUME_SOURCE=generated` (only that value opts out; unset or anything else sends the upload), the generated variant is used as before: the variant snapshot rendered to PDF at `<profile data dir>/applications/<job>/resume-<variant>.pdf`, or on alternate-profile runs the same variant printed with the candidate's `handshake_internal` graduation answer in place of the default one (`printResumeVariant` with a graduation override; nothing else in the frozen document changes; without that answer the run stops before anything changes), with the one-page stop.
Preparation always builds the variant: the package, its verification, the review page, and the fallback rely on it.
Runs planned before this rule keep their decisions: variant decisions print the variant, and a `base_resume` decision whose upload was since replaced stops.
