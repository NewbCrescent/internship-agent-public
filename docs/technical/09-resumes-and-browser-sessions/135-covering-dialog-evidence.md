**Evidence of a dialog that covers the form (Track 39).**
On Lockheed Martin run <run id> (pass 19, 2026-11-25) several Eightfold lists paused with "a dialog covers the form" after the agent signed the typed-name attestation and uploaded the resume, and nothing showed what the dialog was, because only uploads were kept in the job's folder.
Now the first field in a run that a modal dialog leaves unfilled saves one capture of the page while the dialog is still up (`applyDecisions` hands `captureCoveringDialogEvidence` to its `onCoveringDialog` option, `packages/browser/src/handshake-executor.ts`).
The capture holds the full-page screenshot, the visible text, the query-stripped URL, the site's alert text, and each visible modal dialog's text, tag, role, aria label and description, `aria-*` attributes, and buttons (text, aria-label, title, disabled), read by `readCoveringDialogsIn` (`packages/browser/src/announcement-dialog.ts`) without clicking, focusing, or tagging anything.
Nothing in the dialog is clicked, closed, or dismissed by the capture, and the field still pauses as before.
The orchestrator saves it for the run with `saveCoveringDialogEvidenceQuietly` (`packages/agent/src/submit-evidence.ts`) as outcome `covering-dialog` in the run's evidence folder, under the same rules as post-submit evidence: directory mode 700, files mode 600, and every text redacted like the pipeline's notices.
At the start of a run the run's id is chosen before the form is filled, so the capture is saved under it while the page is still open.
A run that already keeps a `covering-dialog` capture saves no second one, whether the dialog comes back in the same fill, on continue, or right before the submit click.
The timeline logs "Covering dialog evidence saved (covering-dialog): <relative path>; view it with pnpm run:evidence --run <ref>.", and a failure to save logs "Covering dialog evidence not saved." and never changes the run.
`pnpm run:evidence --run <ref>` prints the capture's detail (which field it was), a "Covering dialogs: <n>" line, and for each dialog its tag, role, aria attributes, label, description, text, and buttons.
Files written before this field read with `coveringDialogs: null`.
The automatic retry's job-level requeue counts a `covering-dialog` capture as saved before any submit click (`PRE_SUBMIT_OUTCOMES`, `packages/agent/src/automatic-retry.ts`), so it is never read as a submit attempt.
The pause now tells the candidate what to do: "The agent could not fill "<label>": a dialog covers the form, and the agent does not click through or close such a dialog. Open the application in your browser to see what the dialog asks (pnpm run:evidence --run <ref> shows what the agent saw), then answer it here, or fill it in the browser."
Regressions: scenario (e) of `pnpm test:browser:unrecognized-forms` (the `?blocked=dialog` session dialog, now with aria-labelledby, aria-describedby, and two buttons that count clicks), the covering-dialog cases in `pnpm test:browser-worker:local`, and the Track 39 block in `pnpm test:agent:evidence`.
What the dialog on run <run id> was stays unknown until the next real Eightfold run saves its capture.
