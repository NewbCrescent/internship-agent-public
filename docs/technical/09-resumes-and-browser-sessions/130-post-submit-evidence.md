**Post-submit evidence.**
On every outcome except a confirmation, `submitBrowserRun` keeps what the page showed in `<profile data dir>/applications/<job>/submit-evidence/<time>-<run>/` (`packages/agent/src/submit-evidence.ts`; directories mode 700): `screenshot.png` (a full-page screenshot; none once an emailed security code was typed, since it could show the code) and `evidence.json` (mode 600: the outcome, `verification-code` among them, the final URL with its query and fragment removed, the invalid fields with their labels and the site's error texts, the site's error text, the challenge, and the visible text redacted line by line like the pipeline's notices, so emails, URL queries, and long digit runs are removed, capped at 20,000 characters).
The run's timeline logs "Post-submit evidence saved (<outcome>): applications/<job>/submit-evidence/<folder>; view it with pnpm run:evidence --run <ref>."
(a path relative to the data directory only); a failure to save logs "Post-submit evidence not saved." and never changes the outcome.
The evidence stays local: it is never sent to Discord or a model.
`pnpm run:evidence --run <id or 8-character prefix> [--all] [--profile real|demo]` (`packages/agent/scripts/run-evidence.ts`, read only) prints the newest capture (all of them with `--all`): its outcome, URL, invalid fields, site error text, challenge, screenshot path, and redacted text.
Workday stops are saved the same way while the page is still open (`saveWorkdayEvidenceQuietly`, `captureWorkdayEvidence`): outcome `workday-errors` when Workday would not save a step (the run's folder; Workday's errors as invalid fields with their labels and the rest as the site error text; detail "Workday could not save <step>."), and outcome `workday-account` when the account step held the host.
Outcome `workday-entry` is saved when the application did not open (a closed posting, a security check, or neither): in the job's folder `<time>-workday-entry` when no run exists yet, otherwise in the run's; `pnpm run:evidence --job` then prints "Run: none (the application did not open, so no run was saved)".
No run exists yet for an account-step stop, so its folder is the job's, `<time>-workday-account`, with `runId` null, the hold reason as `detail`, and the account email and the host's saved email and password replaced by "[redacted]" in every text (the screenshot may still show the typed email; it stays local).
The timeline logs "Workday evidence saved (<outcome>): <path>; view it with pnpm run:evidence --run <ref>." or "… --job <ref>."; a failure logs "Workday evidence not saved.".
`pnpm run:evidence --job <id or 8-character prefix> [--all]` prints a job's evidence, its runs' and its account-step stops', each with a `Run:` line (`Run: none (the account step stopped before a run was saved)`); both modes print the `Detail:` line when one is stored.
Files written before this field read with `detail: null`.
An Ashby capture also keeps `ashbyNetwork` (Track 22; null on other sites and older files): the network record above, with every message redacted like the visible text; `pnpm run:evidence` prints it as an "Ashby network: <n> GraphQL call(s) recorded; reCAPTCHA token requests: <n> (HTTP …)" line and one line per submit request (its operation, the click it followed, its HTTP status or "no answer"/"request failed", the token kind, the result type, error codes and messages, field-error count, and the block message), or "no submit request was sent".
An Ashby capture also keeps `ashbyDiagnostics` (Track 27; null on other sites and older files): the click checks, request groups, console and page errors, and visible errors above, every text redacted again like the visible text; `pnpm run:evidence` prints them after the network lines.
The local `submit-evidence` suite (`pnpm test:agent:evidence`) covers the files and the command.
