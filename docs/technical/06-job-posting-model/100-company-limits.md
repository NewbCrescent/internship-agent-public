**Company limits.**
The automatic pipeline treats postings as one company when their company names match after `normalizeCompanyName` (packages/domain `company-policy.ts`: case, punctuation, a leading "the", and trailing legal suffixes such as Inc., LLC, Corp. are ignored) or when they share a Workday tenant host.
At most `INTERNSHIP_AGENT_COMPANY_CAP` (default 2, 1–20) automatic applications go to one company per target term: only other postings at that company with a run the pipeline started that is in flight (started, paused, waiting at the submit step, submitting, or a failed submit) or submitted count, filtered by `judgeTerm` when a target term is set.
A run's origin is read from the run-start event its job logged just before it ("… run started automatically from the verified package" for the pipeline; "started from the approved package" or "restarted after …" for the candidate); a run with no such event counts as automatic.
The candidate's own runs, candidate-started runs the candidate submitted, manual-checklist submissions, and cancelled runs never use a slot; a pipeline-started run the candidate approved and submitted still does.
Before each automatic run, and again before an automatic submission, `companyStanding` (packages/agent `company-policy.ts`) recounts; a posting over the cap gets "Company cap: already N applications to <Company>." once on its timeline and is reconsidered on later passes.
Verified packages run in descending current AI fit, so where postings compete for a company's last slot the higher fit takes it (ties keep import order); a posting that already took a slot is never withdrawn for a later, better one.
One graduation profile per company: migration 0029 records each run's profile in `browser_runs.application_profile` (`default` or `transcript`; older runs are read from their decisions as before).
The earliest submitted application at the company, else its earliest filled run of any status, fixes the profile for later automatic runs.
With the default (2028) profile fixed, a form asking for a transcript (or Handshake Quick Apply) stops the automatic run before anything is filled ("Automatic browser run needs you: …"), and a Workday walk stops at the transcript step without going back to change the history; with the transcript (2029) profile fixed, a form without a transcript field still uses the 2029 answers and the resume printed with the 2029 date, and the run stops if no 2029 graduation answer is recorded.
A submission recorded without a run (manual checklist) fixes a profile only for a Handshake-internal posting.
Candidate-started runs are never capped, counted, switched, or blocked; when their profile differs from the company's, the timeline gets "Heads-up: <Company> already received your <year> profile; this run uses your <year> profile."
