The candidate profile holds contact details that application forms ask for (migration 0018): legal first and last name and a mailing address (line 1 and 2, city, state or province, postal code, country).
The candidate enters them on the profile page; the full name is never split into parts.
`pnpm profile:address --profile real|demo [--list | --set-file <address.json> [--dry-run]]` (Track 84) sets the mailing address without the dashboard: the file names only the fields it changes (`addressLine1`, `addressLine2`, `addressCity`, `addressRegion`, `addressPostalCode`, `addressCountry`; an empty string clears one), is checked with the profile schema's own limits before the database is opened, and refuses unknown keys by name.
It saves through the profile page's service (`updateCandidateProfile`) under the workspace's pipeline lock, since a profile save bumps the AI-fit context version, keeps every other profile field, and prints only `set|cleared|unchanged <field> [profile]` (with `would ` on a dry run, which writes nothing) and, with `--list`, `set` or `not set` per field, never a value.
The autofill planner fills a field from them only when the whole label, without its required marker (`*`, `∗`, `✱`, `＊`, "(required)"; recognition strips it and marks the field required), is a standard contact label ("Name" or "Full name" from the profile name, "Email" even in a text box, "Phone", "LinkedIn" / "LinkedIn URL", "GitHub", "Current location" or "Location (City)" as "City, Region" when both are on the profile, "First Name", "Address Line 1", "Postal Code", "Country / Territory", …), chooses a select option only on an exact match, and otherwise pauses; a question that merely mentions a contact word ("Which city would you prefer…") is never filled from them.
A "Phone" question asked as a number box (an Ashby Number question, Track 67) takes the profile phone's digits only, and none when they are fewer than 7 or more than 15.
