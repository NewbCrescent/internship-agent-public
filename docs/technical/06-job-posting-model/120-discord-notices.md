**Discord notices.**
With both `INTERNSHIP_AGENT_DISCORD_BOT_TOKEN` and `INTERNSHIP_AGENT_DISCORD_USER_ID` set (off otherwise), `runPipelinePass` sends the candidate one Discord DM per pass, after it releases the pipeline lock, listing only what is new: held runs (auto-submit holds, plus filled or paused runs when auto-submit is off) with their reasons and each open pause's form label as `Q<n>` (safeguard/CAPTCHA, document, and demographic pauses are marked; "Unlabeled … control N" pauses are summed up as "plus N fields without labels" and the CAPTCHA token field is never listed, while Q numbers keep their pause index), submitted applications (company and title; never the confirmation text), with a line listing the unverified requirements of a posting pursued on AI fit, stopped automatic runs, errors, and a pass that failed.
A policy submit held as a possible submission is listed once per run under "Sent, waiting for the receipt email:", never under errors (Track 85).
`packages/agent/src/pass-notice.ts` builds the items and `src/discord-notify.ts` sends them through Discord REST v10 with `fetch`: it opens the DM channel (`POST /users/@me/channels`), posts messages of at most 2,000 characters with mentions disabled, retries once after a 429's `retry_after` (up to 30 s), and gives each request 10 s. `<workspace data>/discord-notified.json` (mode 600) records the last 2,000 notified items, so an unchanged pass sends nothing and nothing repeats (a held run is notified again only when its open questions change); a failed send logs `Discord notify failed: <status>` (never the token), records nothing so the next pass retries, and never fails the pass.
Messages carry company, title, form question labels, and reasons only; reasons and labels have emails, URL query strings, and digit runs of seven or more redacted, and answers, voice drafts, confirmations, documents, and facts are never read.
The bot must share a Discord server with the candidate.
`pnpm notify:test` sends one "Internship agent connected."
DM (manifest benchmark tier; no gate runs it).
The pipeline does not read or act on replies.
`pnpm discord:read [--limit 20] [--since <ISO or 30m/2h/1d>] [--json]` prints the DM thread for a person or agent to read: `src/discord-read.ts` (`readDiscordDm`) opens the DM channel, then makes only GETs (`/users/@me` for the bot's id, then `/channels/<id>/messages` with a limit of 1-100, default 20, and optional before/after message ids) with the same headers, 10 s timeout, and single 429 retry as sending; it never sends, edits, reacts, or deletes.
Messages come back oldest first as `{ id, at, from: "bot" | "candidate", text }` (bot by the bot's own id or the author's bot flag).
The CLI reads the latest `--limit` messages and keeps those at or after `--since`; human output is `--- <time> BOT:` or `CANDIDATE:` followed by the text, `--json` prints one array.
The token is replaced by `[redacted]` in message text and never printed; failures print `Discord read failed: <status>` (status and Discord code only), and missing settings exit 1 with a fixed message (manifest benchmark entry `discord-read-live`; the fast suite `discord-read` covers it offline).
