`pnpm run:questions --run <id or 8-character prefix> [--profile real|demo]` lists a held run's open questions with the same `Q<n>` numbers as the Discord notice (`pauses[n-1]`), each with its kind, offered options (the first 25), and whether an answer would be saved for reuse or used for that run only and why; it prints no answers.
`pnpm run:answer --run <ref> --q <n> --answer "<text or option>" [--once] [--continue] [--profile real|demo]` answers that pause through `answerRunPause` while holding the workspace's pipeline lock (it refuses while a pass holds it, and in manual checklist mode), then continues the run with `continueBrowserRun` when no question is left open or `--continue` is given; `--continue` without `--q` and `--answer` only continues.
A select or radio answer must be one of the offered options (matched by normalized text) and a checkbox takes yes or no.
It prints `Q<n> saved for reuse`, `Q<n> used once (<reason>)`, the questions still open, and the run's new status, never the answer.
Continuing opens the application in the visible browser, so on the PC run it under `xvfb-run -a`; it passes no voice drafter, so it never calls a model.
The internship Discord session runs these commands for the candidate. run:answer itself never submits.
When the continued run reaches the submit step it prints what happens next (`continuedRunNote`): `It waits for your submit approval; the auto-submit policy is off.`, `It waits for your submit approval: <reason>` when the sweep would not take the run (the candidate started it, a run blocker, an earlier approval or attempt, a possible submission), or that the next pipeline pass submits it under the policy if the target, AI fit, company cap, and daily cap still allow (a pass runs when a watched list changes, or with `pnpm pipeline:run --skip-discovery`).
Both accept `--digest <n>` in place of `--run`: the daily digest's item number, mapped to its run through the digest state file (`discord-digest.json`).
`pnpm run:questions --digest <n>` also lists that item's asks in the digest's order with their `Q<n>` numbers, so a reply such as "1: yes, May 15" answers the first and second of them.
