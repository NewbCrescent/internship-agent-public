GitHub list rows on hosts without a board API resolve through `packages/agent/src/posting-page-sources.ts`, without a model: Dover links (`app.dover.io/apply/{client}/{uuid}`) through the public `api/v1/inbound/application-portal-job/{uuid}` endpoint behind Dover's apply page (inactive or private jobs are unavailable); classic iCIMS links (`{sub}.icims.com/jobs/{id}[/{slug}]/job`) through the job page's `?in_iframe=1` view and its schema.org JobPosting; Workable links (`apply.workable.com/{account}/j/{shortcode}`) through `apply.workable.com/api/v2/accounts/{account}/jobs/{shortcode}` (only published, non-internal jobs; description, requirements, and benefits under their headings); Rippling links (`ats.rippling.com/{board}/jobs/{uuid}`) through `api.rippling.com/platform/api/ats/v1/board/{board}/jobs/{uuid}` (the role section only, never the company boilerplate); Greenhouse `gh_jid` links on employer domains through `boards-api.greenhouse.io`, trying at most two board tokens (the company name squashed, then the employer domain's name) and accepting only a job whose id matches; and Lever EU links (`jobs.eu.lever.co`) through `api.eu.lever.co`.
Any other link falls to a generic career-page source that reads exactly one schema.org JobPosting from the page's JSON-LD (title, description, responsibilities, qualifications, location, `datePosted`, `validThrough`; a past `validThrough` is unavailable).
That source fetches only public hosts (no IP literals, `localhost`, or reserved names such as `.test`, `.local`, or `.internal`), never Handshake, aggregators (LinkedIn, Indeed, Glassdoor, ZipRecruiter, Simplify), the lists' own hosts, or known ATS hosts, and never paths with `apply`, login, or sign-up segments; it follows at most three redirects, all on the same host, accepts only HTML, reads at most 5 MB, and times out after 15 seconds.
The list's age and season filter still runs first, before the scan cap and before any posting request, so only rows listed within `INTERNSHIP_AGENT_DISCOVERY_MAX_AGE_DAYS` are ever requested.
Posting requests are spaced 350 ms apart overall and at most one per 500 ms per host (`packages/agent/src/host-pacer.ts`, shared with the publication-date backfill), and carry the project's `internship-agent-local` user agent.
Two notes name what stayed behind: the unsupported hosts with counts ("Manual review, no supported full-posting source: …") and the reasons postings were unavailable ("Unavailable postings stay for manual review: …", such as an HTTP status, no schema.org JobPosting data, or a redirect away from the posting's site).
Everything unsupported or unavailable stays in the source repository for manual review, as before.
Structured locations from Dover (`location_option` city, state, and country), Workable (`countryCode` when no country name is given), and JSON-LD (`addressCountry`) are joined with the country named in full (ISO alpha-2 codes through `Intl.DisplayNames`, in `packages/agent/src/place-text.ts`), so the place reader never mistakes a code such as "DE" for a US state; `gh_jid` links carry the Greenhouse Office line like the board API, and the list-column location fallback applies to these sources too.
