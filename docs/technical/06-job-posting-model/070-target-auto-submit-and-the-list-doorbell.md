**Target, auto-submit, and the list doorbell.**
`INTERNSHIP_AGENT_TARGET_TERM` (for example `summer-2027`) narrows the automatic pipeline to postings `judgeTargetPosting` (packages/domain `application-target.ts`) does not skip: the term (a title naming the target season, or one silent on term whose description names no other; another season, year, off-cycle month with a year, H1/H2, co-op, or a placement longer than a summer skips; the target season beside another term or a co-op goes to review), a software or adjacent role from the title (software, full-stack, mobile, ML/AI, data engineering or science, infrastructure, SRE, security engineering, or technical research, see the next file; analyst-only, product, design, sales, hardware, and trading titles skip, as do titles named for graduate students (PhD, doctoral, Master's, MBA, research scientist) unless they also name a bachelor's level such as "BS/MS/PhD"), a stated US location (another country skips; none stated goes to review), and the source (`judgeSource`: a posting whose source or apply link is on Handshake by `isHandshakeHost` in packages/jobs, or whose type is `HANDSHAKE_INTERNAL`, skips with "Source: Handshake is out of scope (GitHub lists only)."; the Handshake session code and dashboard panel stay in place), and pay (`judgePay`, the candidate's rule of 2026-11-24, "unpaid inter ships should be ruled out": a title or description that explicitly states the internship is unpaid, such as "(UNPAID)", "unpaid internship", "this position is unpaid", "no compensation will be provided", or "this is a volunteer position", academic or course credit instead of pay, a stipend that is not provided (not one for housing or travel), an uncompensated or volunteer position or title, or an extracted pay of exactly zero, skips with "Pay: the posting says the internship is unpaid." (a research title gets "Pay: research internship is unpaid or for credit.") or "Pay: the posting states zero pay."; silence on pay, stated pay, a stipend, "paid or unpaid internship", plural or negated mentions such as "we never offer unpaid internships", and unrelated phrases such as "unpaid invoices" or "no compensation for travel" pass; a description that says unpaid beside an extracted positive figure goes to review).
`judgeFit` then reads only a current AI assessment (a stale or missing one, or the keyword estimate, never qualifies): below the skip line (50, or the auto-submit bar when it is set lower, never below 40) skips; below the bar, LOW confidence, a WEAK rating, or a gap naming a degree level goes to review; a MODERATE or STRONG judgment at or above the bar may be submitted (user, 2026-11-19).
Off-target postings get no AI call and are not prepared, in discovery and in the pipeline; the pipeline logs "Not pursued for your target: …" once per posting.
`INTERNSHIP_AGENT_AUTO_SUBMIT=1` (with auto-apply and a target; manual checklist mode always turns it off) submits a run right after the automatic fill when the combined decision is `apply`, `autoSubmitBlockers` finds nothing (no open pause, safeguard, voice-drafted answer, kept attachment, or unconfirmed shown answer; the site type holds a run only on SmartRecruiters since Track 80, and a form with no application content holds it on such sites, `079-auto-submit-on-sites-without-an-adapter.md`; a value a form field already showed that the planner left because nothing the candidate saved applies to the question (`SITE_VALUE_KEPT_REASON`, such as Workday's default Country or the Country Phone Code chip) is not a kept attachment; a shown value on a question the catalog recognized but no saved answer settles (no saved fact, needs confirmation, ambiguous, or a saved answer that is not one of the options; `UNCONFIRMED_SITE_VALUE_REASON`) holds the run as unconfirmed, as do shown values recorded by runs planned before 2026-11-25; a kept attachment, such as Handshake's attached resume, holds it as before), and the configured daily cap has room.
Set `INTERNSHIP_AGENT_AUTO_SUBMIT_DAILY_CAP=unlimited` to remove the total daily cap.
Per-company limits and the graduation-profile rule still apply.
A numeric setting (default 10, clamped to 1–50) counts automatic approvals logged since local midnight (`automaticSubmissionsSince` in `pipeline-orchestrator.ts`: each approval belongs to its job's latest run created at or before it, and is released only when that run is known not to have reached the site, that is, its approval was withdrawn (field errors after the click, a challenge, a missing security code) or the failed submit was reopened with `--reopen-unsubmitted` before the job's next run began; a submitted, submitting, failed, cancelled, or still-approved run, or an approval with no run found, counts); `INTERNSHIP_AGENT_AUTO_SUBMIT_MIN_FIT` (default 50, clamped 40–100) is the AI bar.
`approveRunSubmissionAutomatically` records "Submission approved automatically by your auto-submit policy: …" with the basis (which names the AI fit, its rating and confidence, and the bar it met), never an APPROVED event, and `submitBrowserRun` then submits with the usual confirmation check.
A failed automatic submit is logged ("Automatic submission failed: …") and never retried.
On a site whose confirmation page was never captured, a policy submit's outcome is held as a possible submission until a receipt check (Track 80).
A run the pipeline started that reaches the submit step clean later (its last question answered with `pnpm run:answer` or on the application page, or held earlier only by the target, the AI fit, the company cap, or the daily cap) is taken up again at the start of each later pass's browser step (`continuedAutoSubmitRuns` in `packages/agent/src/continued-auto-submit.ts`; candidate decision 2026-11-21) and goes through the same `submitAutomatically` check and submit; the graduation-profile rule is re-checked there against the company's pinned profile, and an answered run's approval basis says some answers were the candidate's own for that run.
Before that sweep, each pass continues a held run the pipeline started whose every question is now answered but that nobody continued (the stop re-check answered its last question, or an answer was saved without a continue), with no voice drafter and no AI review, as `pnpm run:answer --continue` does (`answeredHeldRuns` and `answeredContinueBlocker` in `packages/agent/src/continued-auto-submit.ts`; Track 78); a run that reaches the submit step goes through the sweep in the same pass, and a continue that fails is logged "Automatic browser run failed: the answered run could not be continued: <reason>" and is not tried again until the run changes; runs the candidate started, Workday runs, runs with a safeguard pause, a submit approval, post-submit evidence, or a possible-submission hold, skipped or relabel-held postings, and runs whose package changed are not continued.
The sweep takes only the latest live run of an APPLYING job, started by a "started automatically" event (never a run the candidate started, nor one with no start event), with no other live run, no run blocker, no submit approval, no automatic approval logged since the run was created, no post-submit evidence, confirmation, or confirmed receipt, no active possible-submission hold, the same verified package, AI requirement labels, and a qualified (or pursued-on-fit) verdict; auto-apply off or manual checklist mode skips it.
Other held runs stay at the submit step for the candidate.
Applications use the default (2028) graduation answers unless the form asks for a transcript, which switches the run to the alternate (2029) profile as before.
