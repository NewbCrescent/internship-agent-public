Locations are read from US "City, ST" pairs anywhere in the text and, on a labelled line ("Location: …") or a line that is nothing but a place, from full US state names, Workday's "US-State-City" form, Canadian provinces, and "City, Country" or "Country, City" with country names taken from the runtime's ISO 3166 region names (`packages/jobs/src/place-names.ts`).
An explicit country wins, then a full state name, then a province, then a two-letter state code, so "Toronto, ON, CA" is Canada.
When a labelled line or place line names no country, state, or province, a short table of unambiguous well-known cities decides (`readWellKnownCity`: "Berlin" is Germany, "Paris" France, "South San Francisco" and "NYC" the US; parentheses and words such as Hybrid, Remote, Office, HQ, Area, Metro, and Greater are ignored around them); "City, ST" and an explicit country always win ("Paris, TX" is the US, "London, Ontario" Canada), ambiguous names (Cambridge, Waterloo, Johnston, Durham, Vancouver) are left out, any other bare city stays unknown, and a place mentioned in prose never becomes a location.
`locationCountryCodes(text)` reads one location string the same way.
Discovery writes structured ATS location fields into the `Location:` line (`packages/agent/src/github-job-list-source.ts`): Ashby's location joined with its `address.postalAddress` locality, region, and country (a work-mode-only location such as "Hybrid" gives way to the address; secondary locations follow after "; "), Lever's `allLocations` (else the category location) with the posting's ISO `country` named when there is one location ("Seoul, South Korea"), Greenhouse's offices as a second `Office:` line when they say more than the location, and Workday's country joined to a single location.
The GitHub list's own column is added as `Job list location:` when the board states no location or one that names no readable place.
No posting source reads HTML (every source is a JSON API), so there is no JSON-LD `jobLocation` to read.
Postings stored before this keep their old snapshots; `pnpm backfill:extraction` re-reads them with the city table.
Pay reads trailing units including "-ly" forms ("$45.00 - $55.00 hourly"), ranges joined by dashes, "to", or "and", a leading pay label ("Hourly Rate Band $35 — $55 CAD"), and a currency code before or after the amount; a bare "$" stays USD.
`pnpm backfill:extraction [--profile real|demo] [--apply]` re-reads location and pay for every stored snapshot with the current extractor under the pipeline lock: a dry run reports coverage before and after, postings that would lose a country or USD pay, and samples; `--apply` replaces only `job_locations` and `job_compensation` rows in one transaction, re-verifying every span, and leaves snapshots, requirements, matches, packages, and statuses alone.
No network or model is involved.
