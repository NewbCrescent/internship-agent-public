Answering a held run: each held item carries `run <first 8 characters of browser_runs.id>` (other items carry `job <first 8 characters of jobs.id>`).
`Q<n>` is `pauses[n-1]` of that run at the time of the notice (the array keeps its order).
Answer it with `answerRunPause(runId, pause.fieldId, answer, remember)` (packages/agent/src/browser-orchestrator.ts, the path the application page's run panel uses; sensitive answers are used for that run only and never stored (saved self-identification answers come only from `pnpm profile:facts`); safeguard and upload pauses cannot be answered this way and need the candidate in the browser), then `continueBrowserRun(runId)` refills the form.
Continuing plans every open, unanswered pause again with the current rules (pauses keep their positions); a pause that candidate memory or a rule now answers is marked answered (a sensitive one without copying the option), and statements newly accepted under the standing settings are logged; a demographic field whose fill fails stays sensitive.
A paused run the pipeline started that is answered and reaches the submit step clean is submitted on a later pass under the auto-submit policy (the candidate's decision of 2026-11-21), and one answered without a continue is continued by the next pass (Track 78); a run the candidate started waits for their approval.
