The catalog has two canonical score keys, `sat_score` (400 to 1600) and `act_score` (1 to 36), both global, saved only from the candidate's own answer; "SAT Score" and "Provide your best result on SAT:" map to `sat_score`, a test-type question ("Test Type", "Score type", "Which standardized test did you take?") picks only the one "SAT" or "ACT" option, a score bucket list ("<1200 | 1201 - 1300 | …") picks the one bucket holding the score, and a label naming both tests ("SAT or ACT Score") or a section ("SAT Math score") stays unmapped, so its question-memory answer keeps answering it.
`pnpm profile:answers --promote <id> --key sat_score|act_score [--dry-run]` saves a saved question-memory answer ("1350", or "1350 (SAT)" whose tag must name the key's test) as that fact with the candidate's answer as its provenance (`remembered_answer` and the saved question), keeps the saved answer, writes nothing with `--dry-run`, and never prints the value.
Until the promotion runs, a question mapped to `sat_score` waits as a recognized question with no saved fact, because question memory is read only for unmapped questions.
