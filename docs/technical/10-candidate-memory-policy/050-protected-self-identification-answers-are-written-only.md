Protected self-identification answers are written only by `pnpm profile:facts`.
The mapper still blocks protected questions, and `resolveCandidateQuestion` and `answerCandidateQuestion` refuse protected keys, so a pause answer or the profile page never stores one.
Browser runs fill them only into EEO-role select or radio fields whose label names exactly one category (gender; Hispanic/Latino yes/no; race or ethnicity; veteran; disability; sexual orientation; transgender identity, 2026-11-24), that offer a decline option, and where exactly one option matches (`matchSelfIdentificationOption`, packages/browser `src/ats/self-identification.ts`, read through `savedSelfIdentification`, packages/agent `src/saved-answers.ts`).
Pronoun, LGBTQ+, sex-assigned-at-birth, accommodation, and open prompts never use them, nor do free-text fields; a "mark all that apply" checkbox group with a decline option takes the one matching option, while other checkbox groups (Workday's CC-305 checkboxes) never do; otherwise the field pauses as before and an in-session answer is used for that run only.
The values never enter model inputs (voice drafting and AI fit read no facts), logs, Discord notices, or reports, and the profile page shows them only as "Saved"; the run's decisions in local SQLite record the chosen option.
A filled EEO question is a fill, not a pause, so it does not block auto-submit (candidate request 2026-11-19).
The "How would you describe your …" lead-in is not an open prompt, and "racial/ethnic" labels are EEO questions; a "mark all that apply" list takes the one matching option.
