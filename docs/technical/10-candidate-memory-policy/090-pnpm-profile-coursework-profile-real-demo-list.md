`pnpm profile:coursework --profile real|demo [--list | --set-file <coursework.json> [--dry-run]]` saves the candidate's relevant courses, entered by the candidate from their own transcript (the transcript file is never read).
The file is `{ "school": "<school>", "courses": [{ "code": "<DEPT 101>", "title": "<course title>", "term": "<Fall 2025>", "status": "completed | in_progress" }] }`.
The whole file is validated before the database is opened: strict keys (so a grade or any other extra key is rejected, with its path), the two statuses, at most 40 courses, no duplicate codes (compared as evidence IDs, so `CS 61B`, `cs 61b`, and `CS-61B` collide), no runs of 8 or more digits (an ID-like number), and whitespace trimmed and collapsed.
The set is replaced in one transaction under the workspace's pipeline lock (a context bump mid-pass would make in-flight fit saves fail); an identical set writes nothing and prints `unchanged: <n> courses (<c> completed, <p> in progress)`.
Otherwise it prints `school: …`, `added|changed <code>: <title> (<term>, <status>)`, `removed <code>: <title>`, or `reordered courses`, then `saved <summary>` (or `cleared all courses` for an empty list) and `answer: <the coursework answer>`; `--dry-run` prefixes each line with `would ` and writes nothing, and `--list` (or no flag) shows the saved courses as `<code> | <title> | <term> | <status>` and the answer.
