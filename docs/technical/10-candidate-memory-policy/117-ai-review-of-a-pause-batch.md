The AI review of a pause batch (`packages/agent/src/pause-review.ts`) runs once when a run pauses on questions the deterministic checks could not answer: after start plans the form (and its voice drafts), after continue plans the open questions again, and after each Workday step is planned; never on a run showing a CAPTCHA and never on Workday's submit walk.
It looks only at open question pauses the stop re-check may look at (see 115) that are not demographic, contact, upload, consent or attestation statements, or text-message consent questions.
One reviewer serves one start, continue, or Workday walk: it makes at most one model call per distinct batch and at most three calls in all; no eligible question means no call.
It sends the posting's company, title, and places, each question's label, kind, and offered options (at most 50, each clipped to 120 characters), and the saved candidate facts it may match: reusable catalog facts other than coursework and the standard legal answers, with values only for standard-sensitivity facts.
Sensitive facts are sent only as `saved`, never with their value.
Nothing about the protected self-identification categories is sent: no key, description, value, or saved or not-saved marker, so the model cannot tell whether the candidate saved one.
It never sends the candidate's name, contact details, address, student ID, question-memory answers, secrets, or browser state.
The model returns one review per question: `saved_answer` with a fact key and the offered option it maps to, `needs_candidate` with a reason, or `draft` with a short suggestion for an open-ended prompt.
A `saved_answer` is applied only when every check passes: the key was sent and is a standard-sensitivity catalog fact (not coursework, not a standard legal answer); the question mapper leaves the question unmapped; it states no fact group (citizenship, clearance, debarment, conflicts, criminal history, prior employment); no never-reuse rule applies; a current reusable fact applies here (the company's, else the posting country's, else the global one); the field takes it (a list needs exactly one matching offered option, which must agree with the model's option; text, number, and URL boxes take text or yes/no facts, never dates; a single checkbox takes only yes/no); and the recorded-wording store exists.
An applied match fills the field with the fact (basis `fact`) and the reason `aiReviewMatchReason(label)` (`AI review matched "<label>" to your saved answer.`), drops the pause at start or marks it answered on continue and Workday, logs `AI review matched '<label>' to saved answer <key> (<scope>).`, and records the wording with source `ai_review`, so later runs reuse it deterministically, still marked with that reason.
A match that fails a check waits for the candidate with `AI review: AI review suggested a saved answer, but it did not pass the checks (<check>); answer it yourself.` added to its question.
A `needs_candidate` review adds `AI review: <reason>` to the question, which stays open.
A `draft` is kept only for a text area or an open-ended prompt that has no draft yet: it is stored on the pause with source `pause_review`, never filled, never saved as a fact or question-memory answer, and shown by `pnpm run:questions` as `AI suggestion, not sent`; `pnpm run:answer --q <n> --use-draft` answers with it for that run only.
An answer the AI review matched after every deterministic guardrail passed does not hold the run from automatic submission (`autoSubmitBlockers`); every other auto-submit rule still applies.
That is the candidate's decision of 2026-11-26: "auto-submit. i want applicatioms to go out asap when they are ready and good".
The auto-submit approval event names each question the AI review matched, by its label only (no key, value, or option): `AI review matched your saved answers for: "<label>", ….`
A draft the AI review suggested holds the run only while its question is unanswered; once the candidate answers it through `pnpm run:answer` (with `--use-draft` or their own text) it is the candidate's answer and no longer holds the run, as with voice drafts.
Any model failure (no answer, a timeout, invalid output) leaves every pause as it was and logs `AI review could not run (<error>); the questions wait for you as before.`; the provider's own bounded retries are the only retries.
Each call adds a `model_invocations` row (task `application.pause_review`, tier `cheap`; failures too) and one timeline line with the questions looked at, matches, questions still waiting, drafts, duration, and tokens.
The review is on whenever a model is configured; `INTERNSHIP_AGENT_PAUSE_REVIEW=0` turns it off, and `pnpm run:answer` and `pnpm questions:recheck` never call it.
Tests use a fake model provider (`testing-harness/agent/pause-review.integration.test.ts`); live ATS pages and the real model's answer quality are not covered.
