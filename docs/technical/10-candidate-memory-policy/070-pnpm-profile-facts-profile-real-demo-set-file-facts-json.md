`pnpm profile:facts --profile real|demo [--set-file <facts.json>] [--dry-run]` writes the candidate's explicitly given answers.
The file is `{ "facts": [{ "key": "<fact key>", "scope": <{ "kind": "global" } (the default) | { "kind": "country", "code": "US" } | { "kind": "company", "name": "<employer>" }>, "value": <true | false | "text" | "YYYY-MM-DD">, "note": "<optional provenance>" }], "revoke": [{ "key": "<fact key>", "scope": { ... } }] }`; a protected value is one of its listed categories, for example `"eeo_gender": "<one of: male | female | non_binary>"`, `"eeo_sexual_orientation": "<one of: heterosexual | gay | lesbian | bisexual | pansexual | asexual | queer>"`, or `"eeo_transgender": "<one of: transgender | not_transgender>"`; `willing_background_check` is `true | false` (global) and `willing_to_relocate_at_own_expense` is `true | false` with a country scope (for example `{ "kind": "country", "code": "US" }`).
(Track 83) `act_taken` and `available_full_time` are `true | false` (global), and `county` is `"<county name>"` (global).
(Track 87) `prior_internships_count` is `"<number>"` (one or two digits, global), and `has_outstanding_offers` is `true | false` (global).
Everything is validated before anything is written.
Facts are saved with source `user` and source detail kind `profile` carrying the note; unchanged values are skipped, and a country relocation answer supersedes the current global one.
It prints `set|unchanged|superseded|revoked <key> [<scope>]: <value>` with protected values shown as `set`, never echoed, even in errors; `--dry-run` prints `would …` and writes nothing, and without `--set-file` it lists the current facts the same way.
Only a write to a fact the AI fit reads (`FIT_CONTEXT_FACT_KEYS`, today `graduation_date`) bumps the AI-fit context version (migration 0034), so cached AI fits become stale and are analyzed again; other fact writes, here or from `pnpm run:answer`, leave them current.
